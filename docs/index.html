Enterprise Document Q&A

A question-answering assistant for internal policy documents. Every answer cites the source document and page, the assistant declines when the evidence is too weak instead of guessing, and role-based access control keeps restricted files out of answers for users who aren't cleared to see them. This demo runs entirely in your browser.

    How it works

    1. Ingest. PDF and Word documents are split into chunks, and each chunk keeps its document title, page number and classification (public, internal, confidential or restricted).
    2. Filter by role. Before any search runs, chunks above the user's clearance are removed, so a restricted file can never reach an answer.
    3. Retrieve. Each question is scored with BM25 and TF-IDF, and the two rankings are merged with reciprocal rank fusion.
    4. Answer or decline. The answer is taken from the best matching sentences and cited by document and page. If too few of the question's key terms appear in the top passages, the assistant declines.

    This page is a JavaScript port of the Python retrieval code. The full app adds a FastAPI backend, a Streamlit interface, document upload, optional LLM-generated answers and RAGAS evaluation.

    Evaluation

    All nine combinations of three chunk sizes (256, 512, 1024 characters) and three retrievers were compared on an 11-question test set. Best configuration: 512-character chunks with hybrid BM25 + TF-IDF.

    Limitations

    • The test set is small (11 questions), and the local metrics are lexical overlap checks, not semantic faithfulness scores.
    • Answers are quoted extracts, so they read less naturally than LLM-generated answers.
    • The documents are synthetic and generated for this demo.
